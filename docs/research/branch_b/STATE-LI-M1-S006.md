## 4. Evidence labels and source authority must not collapse

**DEMONSTRATED_LOCAL:** the specific executed synthetic model/test result.  
**SUPPORTED_DOCUMENTATION:** project document or official technical reference, with date and scope.  
**SUPPORTED_CODE:** behavior of the inspected source file/body; does not establish its live success.  
**AUTHOR_REPORTED_CAPTURE:** dated capture/operation claim by a source author, not our observation.  
**HAND_WRITTEN_FIXTURE:** an invented/historical-shape fixture, never proof of live support.  
**SOURCE_FIXTURE_PROVENANCE_UNESTABLISHED:** exact repository bytes are available, but derivation from a real capture is not established. An associated parser-verification claim stays separate.  
**INFERENCE:** reasoning supported by identified evidence, not directly observed implementation.  
**PROVISIONAL:** candidate design choice, revisable.  
**DISPUTED/UNRESOLVED_SCOPE:** source conflict or uncertain semantic scope.  
**REFUTED_AS_STATED:** a specific hypothesis has a concrete counterexample.  
**UNTESTED:** no performed relevant check.  
**BLOCKED_BY_ENVIRONMENT:** named experiment cannot run with current accessible data/services, not a global stop while other useful work remains.  
**DEFERRED:** useful but not selected in the bounded pass.

**SYNTHETIC_DOCUMENTATION_SHAPED:** locally invented safe inputs exercising documented supplier envelope semantics, not downloaded provider output or native capture. **PUBLISHED_CONTRACT_FIT:** screening against retrieved program terms with scope/date/exception qualifications; not legal advice, an entitlement decision or service validation.

## 7. The provisional architecture separates acquisition from recoverable delivery

Current candidate boundary:

```text
source-specific read mechanism
  -> immutable permitted raw evidence + capture context
  -> source-specific extraction/reconstruction
  -> stable observations, relationships, provenance and honest coverage
  -> durable enumerable history or equivalent tested replay source
  -> idempotent M2 admission with durable checkpoint
  -> interpretation outside M1
```

This is a responsibility model, not chosen services, schemas, storage products or a frozen transport.

Required distinctions: full scoped source object; delivery attempt; source content/version; source observation; capture versus reprocessing run; source time versus collection/delivery time; collection reason/watch revision; visibility versus deletion; metric observation versus a derived measure; raw bytes versus interpretation.

A content representation differing from the last one is not sufficient to declare an edit. A repeated capture normalized differently needs a correction path, not a new source-observation timestamp. Full publication/source-modification timestamps, authorship, media, references, access permissions and coverage need exact target-contract mapping beyond this laboratory.

The evidence-history consumer may use ordered events, ordered runs plus immutable pages, or another replay-equivalent design. A webhook is a notification unless proven to be a durable retained feed. Documented latest-only compatibility is permitted only with its reduced guarantee explicit. No M1→M2 interface change has been implemented in production.

**WR-002 refinement:** source-specific reconstruction must preserve raw root positions, resolved entities, unresolved/conflicting references and declared field sufficiency separately. A populated identity-only entity must not satisfy a richer read by silently merging older fields. The new `representation_status` is limited to supported-shape resolution and the caller's explicit root checks; source completeness remains unknown. Unknown collection shape is not empty success. Query/decorator/variable/root/field contract must be validated together before promotion.

No source parser has yet been integrated into the E001–E004 durable admission model or the real M1/M2 boundary. The raw hashes and JSON pointers from WR002/003 are not raw persistence or a complete EvidenceEnvelope.

**WR-003 refinement:** preserve collection view identity separately from candidate activity identity and collection target. The watched profile is not automatically the author. Excerpts and engager/person summaries remain derived projections, never replacements for source occurrences. Native count names, explicit0, missing, null, invalid values, container type and target semantics remain distinct. Preserve returned paging/token evidence before projection; do not derive source completion from excerpt count or person deduplication. Multiple acquisition lanes need their own progress and typed failure beside partial records; this persistent lane design is proposed, not implemented. A current full post requires richer author/reshare/context evidence than the fixture provides.

**WR-004 refinement:** read meaning belongs in the validated recipe contract, not only its operation-family prefix, response shape or success status. Preserve expected population, target kind, access context, ordering, root membership, actor/body/metric bindings and paging semantics through an equivalent replacement. A changed population can be a separately requested lane, never silent repair. E016 only compares NOS-side declarations; actual response tests and existing M1 approval remain necessary. No new production gate or orchestration system was built.

The richer legacy inventory also preserves co-recorded activity/share and actor-related identifiers as associations with pointers, not merged identities. View labels, display-name equality/difference and numeric-ID/relative-time calculations do not certify a reshare, actor identity or source publication time. Original/reshare extraction remains pending an actual sufficiently evidenced representation. Raw hashes remain hashes, not persisted evidence.

**WR-005 refinement:** a receipt of supplier-projected data, a supplier collection/cache generation, a native source observation and a processing replay remain distinct. Store exact permitted supplier bytes before interpreting; do not label them native raw without supporting sidecar/lineage. Preserve supplier computation/warnings/dropped items and provider-only completion separately. Retry identity is per bounded acquisition attempt group, not the permanent watch key. Provider source-capture time may remain unknown even when NOS receipt time is precise. Retention and export rights are route-specific and apply to copies/derived dependencies as appropriate; no permanent keep-all inference from immutability.

The actual M2 boundary requires timezone-aware `observed_at`. A future mapping must express that NOS observed a provider artifact at receipt time, with source age unknown, rather than silently claiming a contemporaneous LinkedIn observation. If the actual contract cannot express this difference, that is an H09 adapter/schema gap. No such mapping or history/admission integration was built in WR005. The new receipt hash/quality output remains an offline inspection, not storage or permission enforcement.

**WR-006 refinement:** keep transport facts, diagnostic hypothesis and stop decision separate. Raw permitted response persistence precedes JSON interpretation, but a failure to store raw bytes must not erase a security/rate stop. A failure to store safety state disables new logical admissions in the affected local model. A classifier's JSON-candidate result is not successful evidence or page completion. Never announce a proven challenge from a generic status/word alone; record an appropriate conservative hold and the uncertain cause.

Independent stop reasons have their own scope, revision and not-before state. Acknowledging a challenge must not erase a rate hold; success from an already-admitted attempt does not clear a newer stop. Task holds accompany account/session holds so the same trusted task cannot resume just by changing identity.429's upstream limit scope remains unknown; the conservative account+origin and task scope is a local design choice, not a measured platform rule. Source-signalled delays are not shortened to a convenient default; absent/invalid delays require explicit external policy.

The SQLite gate orders logical admission against committed holds only. It does **not** stop sockets, revoke work already admitted, authenticate operators, replace M1's ledger or enforce a distributed dispatch fence. The exact copied preflight interleaving creates concrete H16 test debt. Raw filesystem and safety DB remain separate, with orphan/retention/power-loss/backup questions open. The local original model's fixed same-task reassignment flaw and its trusted-lineage boundary must survive continuation.
